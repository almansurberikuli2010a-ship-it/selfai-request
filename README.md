# selfai

Плагин для Claude Code с тремя скилами. Первые два заставляют ИИ-агентов делать
ровно то, что просили: не писать лишнего, не ломать рабочее и останавливаться,
когда работа готова. Третий по тому же принципу делает конспекты уроков.

| Скил | Что делает |
|---|---|
| `/selfai:selfai-request` | Делает задачу силами команды агентов. Без задачи сначала проверяет проект. |
| `/selfai:selfai-prompt` | Делает мета-промпт для другой работы: статей, расчётов, отчётов. |
| `/selfai:obsidian-konspekt` | Делает конспект по урокам для Obsidian: только факты из учебника, простыми словами. |

Это ранняя версия: полностью на настоящем проекте скилы ещё не прогонялись.

## Установка

В Claude Code выполните две команды:

```
/plugin marketplace add almansurberikuli2010a-ship-it/selfai-request
/plugin install selfai@selfai
```

После установки начните новую сессию, чтобы команды появились в списке.

Обновить до новой версии:

```
/plugin marketplace update selfai
```

## Быстрый старт

Сделать задачу в проекте с кодом:

```
/selfai:selfai-request добавь на сайт переключатель тёмной темы
```

Узнать, что в проекте стоит исправить:

```
/selfai:selfai-request
```

Сделать мета-промпт для работы не с кодом:

```
/selfai:selfai-prompt для написания статей в блог
```

Сделать конспект уроков по учебнику:

```
/selfai:obsidian-konspekt учебник §12–15
```

## Зачем это нужно

Если сказать агенту «улучши проект», он понимает это как «напиши больше»: добавляет
файлы, обёртки и возможности, о которых не просили. Эти скилы убирают причину:

- задача превращается в короткий список проверяемых требований;
- один агент делает, другой проверяет и верит только факту, а не словам;
- когда все требования выполнены, работа останавливается;
- агенту прямо разрешено ничего не делать, если делать нечего.

## selfai-request

### Режим 1. Сделать задачу

Вызов: `/selfai:selfai-request` и текст задачи.

Что происходит:

1. Ведущий смотрит проект и составляет документ с заданием. Документ сохраняется
   в файл `selfai-request.md` в корне проекта.
2. Если задачу можно понять по-разному и от этого зависит результат, ведущий
   спрашивает вас. Иначе начинает сразу.
3. Судья пишет по одному тесту на каждое требование и сохраняет состояние проекта.
4. Дальше идут круги: Строитель пишет код, Судья всё запускает заново.
5. Когда работа сделана, один раз работает Чистильщик и убирает лишнее.
6. Ведущий пишет вам итог.

Что в документе с заданием:

| Часть | Что в ней |
|---|---|
| 1. Задача | Ваш текст слово в слово |
| 2. Что должно получиться | Одно предложение |
| 3. Договорённости | Имя главного файла, команда запуска, как понята задача |
| 4. Сценарии | До десяти требований, которые можно проверить запуском |
| 5. Проверить руками | То, что запуском проверить нельзя |
| 6. Не делать | До пяти вещей, которые агент захочет добавить сам |
| 7. Правила | Кто что делает и когда всё останавливается |

Кто что делает:

| Роль | Что делает | Чего не делает |
|---|---|---|
| Ведущий | Запускает остальных по очереди, считает круги, пишет итог | Не пишет код и не проверяет |
| Строитель | Пишет или чинит код под требования | Не правит тесты, не добавляет непрошеное |
| Судья | Пишет тесты, запускает, возвращает проект назад, если стало хуже | Не пишет другой код, не предлагает улучшений |
| Чистильщик | Удаляет неиспользуемое из того, что добавил Строитель | Не переписывает и не трогает остальной проект |

Когда работа останавливается:

- все сценарии, сборка и старые тесты проходят — работа сделана;
- два круга подряд пройденных сценариев не стало больше — работа не сделана;
- прошло разрешённое число кругов (обычно пять) — работа не сделана.

Что вы получите в конце: сделана работа или нет, какие сценарии проходят, какие
нет, что заметил Строитель и список для проверки руками. Файл `selfai-request.md`
после этого можно удалить.

### Режим 2. Проверить проект

Вызов: `/selfai:selfai-request` без текста. Работает только для кода.

Агент читает проект, запускает сборку, тесты и саму программу и ничего не меняет.
В отчёт попадает только то, что подтверждено запуском или точным местом в коде.

Что считается недостатком: программа не делает нужного, падает на обычных данных,
портит данные, не проходят сборка или тесты, дыра в безопасности, неиспользуемый код.

Что недостатком не считается: «можно красивее», отсутствие тестов и документации,
если из-за этого ничего не ломается, и возможности, о которых не просили.

После отчёта ведущий спросит, что чинить. Выбранная строка становится задачей
и уходит в режим 1. За один раз берётся одна задача.

### Работа по своему мета-промпту

Встроенный мета-промпт рассчитан на код. Для другой работы сделайте свой через
`/selfai:selfai-prompt`, сохраните в файл и назовите этот файл при вызове:

```
/selfai:selfai-request по мета-промпту blog-prompt.md напиши статью о том, как выбрать велосипед
```

Роли в своём мета-промпте могут называться иначе, например Автор вместо Строителя.

## selfai-prompt

Вызов: `/selfai:selfai-prompt` и для какой работы нужен мета-промпт.

Скил берёт встроенный мета-промпт как образец и делает такой же для другой работы.

Что остаётся как в образце: семь частей документа, четыре роли, три условия
остановки и право агента ничего не делать.

Что заменяется под новую работу:

| Что | В образце для кода | Пример для статей |
|---|---|---|
| Способ проверки | Запуск программы | Посчитать слова, сверить число с источником |
| Самая дорогая ошибка | Потеря данных | Выдуманный факт |
| Что добавляют без спроса | Файлы, классы, библиотеки | Лишние разделы, вступления |
| Что считается лишним | Неиспользуемый код | Повторы и текст не по теме |

Что вы получите: мета-промпт в блоке кода, список замен, список того, что скил
решил сам, и что осталось непроверенным. В файл он сохраняет только по просьбе.

### Поправить готовый мета-промпт

Дайте скилу готовый текст. Он не пишет новый, а сверяет ваш с образцом и исправляет
найденное.

### Проверить мета-промпт на деле

```
/selfai:selfai-prompt проверь blog-prompt.md
```

Скил запускает двух агентов. Первый выполняет мета-промпт на настоящей задаче
и пишет, где пришлось гадать. Второй ищет фразы, которые можно понять не так.
Потом скил исправляет найденное и говорит, что изменил. Проверка идёт несколько
минут и запускается только по просьбе.

## obsidian-konspekt

Вызов: `/selfai:obsidian-konspekt` и учебник: файлы или текст параграфов. Можно
назвать разделы конспекта, например «разделы: Себептері, Барысы, Экономикалық
салдары». Если не назвать, скил возьмёт разделы из самого параграфа.

Что получится: папка, где на каждый урок одна заметка — `01 Тема.md`,
`02 Тема.md` и так далее. Её открывают в Obsidian: «Открыть папку как хранилище».

Как написан конспект:

- на языке учебника;
- текстом, как документация: заголовки, короткие абзацы, списки, без таблиц;
- полными предложениями простыми словами, одно предложение — один факт;
- даты, имена и термины выделены жирным, после каждого абзаца — страница учебника;
- если для раздела в учебнике ничего нет, написано «Оқулықта жоқ.»,
  а не дописано из памяти.

Что убирается: оценки («ұлы», «великий»), вступления, повторы, рассуждения автора
и вопросы «ойланыңыз».

Как проверяется: скрипт сверяет каждое число в конспекте с учебником, находит
таблицы и показывает годы, которые есть в учебнике, но не попали в конспект.
Имена и термины скил сверяет поиском по учебнику сам.

Чтобы проверка работала, давайте скилу только те параграфы, по которым нужен
конспект: иначе в «возможно пропущено» попадут годы из других уроков.

## Как они работают вместе

```
/selfai:selfai-prompt для написания статей в блог
    → сохранить результат в blog-prompt.md
/selfai:selfai-prompt проверь blog-prompt.md
    → исправленный мета-промпт
/selfai:selfai-request по мета-промпту blog-prompt.md напиши статью о выборе велосипеда
    → готовая статья и итог от ведущего
```

Для кода первые два шага не нужны: `/selfai:selfai-request` сразу работает
по встроенному мета-промпту.

```

└── obsidian-konspekt/

```

## Как поменять правила

Правила для агентов лежат в `skills/selfai-request/references/document.md`. Тот же
текст лежит в `skills/selfai-prompt/references/template.md` как образец. Если
меняете один файл, поменяйте и второй, иначе новые мета-промпты будут делаться
по старому образцу. После изменений поднимите `version` в `.claude-plugin/plugin.json`
и в `.claude-plugin/marketplace.json`, чтобы у пользователей сработало обновление.

## Что стоит знать заранее

- Скилы не прогонялись полностью на настоящем проекте. Число кругов и другие числа
  в правилах выбраны на глаз.
- Для работы, где мало что можно проверить по факту (внешний вид, стиль текста),
  большая часть требований уйдёт в «Проверить руками», и пользы от Судьи будет мало.
- Проверка проекта работает только для кода.
- Каждая роль запускается отдельным агентом, поэтому большая задача занимает
  заметное время.
- В проекте без git Судья сохраняет состояние копией папки.
